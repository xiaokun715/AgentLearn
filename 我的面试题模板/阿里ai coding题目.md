# Agent 长任务运行与上下文管理系统

发布负责人需要 Agent 阅读多份较长的资料，评审 Orion 1.4 能否发布。早期提出的日志合规和回滚要求，到了最后仍然有效；阅读中途，负责人又把目标从“对外灰度”改成“仅内部验证”。如果上下文整理丢掉约束、重启后继续旧目标，结论就可能失效。

请建设一个本地可运行的长任务工作台，帮助用户推进这项评审、正常暂停后继续，并比较不同上下文策略。CLI、TUI、Web 均可，最多 **120 分钟**，允许全程使用 AI。

## 用户需要完成的三个流程

1. **启动与查看。** 载入任务和资料，在每次模型输入预算内推进。用户能看见当前有效要求、进度、已取得的证据和模型/工具活动；保存原始证据不等于每次全部发送给模型。
2. **暂停与接续。** 读完 `doc-a`、`doc-b` 后正常暂停，退出进程；应用提供的需求修订，在新进程中继续。保留已完成工作和证据，使用当前有效要求，不把从头重跑当作接续。
3. **策略对照。** 在相互独立的实验中，以简单基线和自选上下文策略处理同一任务、同一修订、同一资料与预算。保存结果、实际模型输入/输出、用量和证据，生成可查看的比较。两次实验的状态不能互相污染；无需证明自选策略必定优于基线，有依据的负结果也有效。

## 已提供的材料

- `data/`：任务、修订、资料目录及四份长资料。
- `DATA.md`：资料与修订语义、业务证据边界。
- `support/`：只读资料工具、输入测量函数和离线协议模拟器，不含任务运行器。
- `MODEL.md`：模型调用与预算说明、离线验证范围、真实模型接入条件。
- `SUBMISSION.md`：启动、操作与简短过程记录要求。

先确认材料工具可用：

```sh
python3 -m support.material_tools list
python3 -m support.model_mock --request data/mock-request.json
```

## 交付与边界

交付可运行系统、源码、三个完整操作示例、数据流说明和自建验证。任务状态、上下文组织、压缩策略、规划表达、模块和存储格式由你设计，不要求补指定函数或遵循固定界面。

默认可离线独立完成。模拟器只验证协议和工程流程；离线最终产物是当前要求、可核查证据、模拟输出及策略对照，不能据此宣称真实模型推理或压缩质量提升。可在提交中附独立人工核查意见，并注明来源。

只有发题方明确提供统一真实模型资源时，才增加真实模式实验；目前材料不包含可用 API，不要求自行付费。无需跨任务长期记忆、多 Agent、并发、实时服务或任意时刻崩溃恢复。说明已完成范围和限制。
