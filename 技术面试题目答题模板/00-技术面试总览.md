## 二、复习路线（建议 2～4 周）

### 第一阶段：建立主干（3～4 天）

1. **01 Agent 基础与架构**：能画出一个 Agent 系统的分层图，讲清运行时、状态、工具、上下文、编排各自负责什么。
2. **02 Prompt 与模型调用**：能讲清结构化输出、Function Calling、流式、模型选型和成本控制。
3. **04 工具与可靠性**：理解「模型只提议，系统负责执行」，重点是幂等、重试边界和副作用。

### 第二阶段：补核心能力（4～5 天）

4. **03 RAG**：掌握完整链路和评测方法，能解释为什么「向量检索不是万能的」。
5. **05 记忆与上下文**：区分短期/长期记忆，理解压缩不可逆和记忆污染。
6. **06 编排与多 Agent**：能说清什么时候用固定 Workflow、什么时候用动态路由。

### 第三阶段：生产化（4～5 天）

7. **07 网关与调度**：容量估算、限流、队列、Lease、Checkpoint、优雅取消。
8. **08 评测与排障**：评测集、归因分析、可观测性、线上事故处理。
9. **09 安全与风控**：Prompt Injection、Guardrails、最小权限、审批、审计。

### 第四阶段：输出与模拟（3～4 天）

10. **10 系统设计**：按「需求—容量—架构—数据流—失败处理—取舍」练 3 个完整设计题。
11. **串讲项目**：把 AI4Test 讲成 2 分钟、5 分钟、15 分钟三个版本。
12. **模拟追问**：每个设计至少准备「为什么不用另一种方案」「出问题怎么查」「怎么衡量」。

## 三、答题通用结构

技术题不要一上来堆名词，建议按四层回答：

1. **一句话结论**：先给判断，例如「我会把执行层和编排层分开」。
2. **原理与边界**：这个方案解决什么问题、不解决什么问题。
3. **项目落地**：我在 AI4Test / AgentLearn 里怎么做的，遇到什么坑。
4. **取舍与验证**：代价是什么、怎么衡量、什么情况下会换方案。

面试官更看重的是「你为什么这么选」，而不是「你知道多少名词」。

## 五、项目故事映射

同一套项目素材，可以按题目抽取不同侧面：

| 题目类型 | 抽取的侧面 |
|---|---|
| 架构设计 | provider / gateway / runtime / orchestration 分层；依赖方向约束 |
| 可靠性 | 工具幂等、Lease、Checkpoint、in_flight / uncertain 状态 |
| 编排 | Agent Pool、能力标签、统一评分、Workflow Validator |
| 上下文 | 多级压缩、任务状态压缩、检索记忆 |
| 高并发 | 多级限流、准入控制、WFQ、Singleflight、语义缓存 |
| 评测 | Golden Set、轨迹归因、版本指纹、CI 门禁 |
| 安全 | Guardrails Pipeline、工具白名单、沙箱、审批 |
| 排障 | 故障上下文、证据驱动假设、受控恢复、经验库 |

## 六、使用说明

- 每份文档中的答案都是「可口述版本」，不是论文；面试时按题目删减。
- 涉及数字的地方用真实数据；没有精确数据就用「明显下降」「从不可用变为可用」这类可解释表述。
- 每份文档末尾有「高频追问」，用于自查是否真的理解，而不是背答案。
- 建议先看总览，再按自己的薄弱项选读，不要从第一页顺序背到最后。
