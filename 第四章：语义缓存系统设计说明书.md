# SemanticCache Demo 设计说明书

## 1. 项目概述

### 1.1 项目名称

```text
semantic-cache
```

目标是实现一个简化版的：

> **LLM Semantic Cache / 语义缓存系统**

支持：

* Prompt Normalization
* Embedding
* Vector Similarity Search
* Threshold Policy
* Cache Hit / Miss
* TTL
* Invalidation
* Safety Validation
* Cache Metrics
* Agent 子任务缓存

---

# 2. 为什么需要 Semantic Cache

普通缓存：

```text
"什么是 TCP？"
```

只能命中：

```text
"什么是 TCP？"
```

但是：

```text
"请解释一下 TCP 协议"
"TCP 是干什么的？"
"能介绍一下 TCP 吗？"
"TCP 的作用是什么？"
```

这些问题：

```text
字符串不同
```

但：

```text
语义高度相似
```

Semantic Cache 的目标就是：

```text
Query A
"什么是 TCP？"
       │
       ▼
   Embedding
       │
       ▼
Vector A
       │
       ▼
Vector DB
       │
       ├── Vector B
       │
       ▼
Similarity = 0.94
       │
       ▼
Cache HIT
       │
       ▼
直接返回历史答案
```

因此：

> **Semantic Cache 本质上是“基于语义相似度的缓存”。**

# 6. Prompt Normalizer

第一步不要直接 Embedding 原始 Prompt。

例如：

```text
"  什么是 TCP？  "
```

和：

```text
"什么是TCP？"
```

实际上应该视为同一个问题。

所以：

```text
Raw Prompt
   ↓
Normalizer
   ↓
Canonical Prompt
```

---

## 6.1 最简单的 Normalizer

```python
class PromptNormalizer:

    def normalize(self, prompt: str) -> str:
        prompt = prompt.strip()

        prompt = " ".join(
            prompt.split()
        )

        return prompt
```

例如：

```text
"  什么是   TCP？  "
```

变成：

```text
"什么是 TCP？"
```

---

# 7. 不能只做字符串 Normalization

这是一个重要问题。

Normalizer 解决：

```text
空格
大小写
格式
特殊字符
```

但解决不了：

```text
"什么是TCP？"

"TCP协议是干什么的？"
```

因此：

```text
Normalization
     ↓
解决文本形式差异

Embedding
     ↓
解决语义差异
```

二者不是一回事。

# 8. Chat Prompt 如何 Normalization

实际 LLM 请求通常不是：

```text
prompt: str
```

而是：

```json
{
  "messages": [
    {
      "role": "system",
      "content": "你是一个AI助手"
    },
    {
      "role": "user",
      "content": "什么是TCP？"
    }
  ]
}
```

因此 Cache Key 不能只取：

```text
user.content
```

否则：

```text
System Prompt A
+
User Question
```

和：

```text
System Prompt B
+
User Question
```

可能错误命中。

建议 Canonical Request：

```json
{
  "model": "qwen",
  "messages": [
    {
      "role": "system",
      "content": "你是一个AI助手"
    },
    {
      "role": "user",
      "content": "什么是TCP？"
    }
  ],
  "temperature": 0
}
```

# 9. Cache Fingerprint

建议生成：

```text
canonical_request
       ↓
SHA256
       ↓
exact_key
```

例如：

```python
import hashlib
import json


def fingerprint(request):

    canonical = json.dumps(
        request,
        sort_keys=True,
        ensure_ascii=False
    )

    return hashlib.sha256(
        canonical.encode("utf-8")
    ).hexdigest()
```

这样可以同时支持：

```text
Exact Cache
+
Semantic Cache
```

# 12. Similarity Search

假设：

```text
Query Vector
      │
      ▼
Vector Database
      │
      ▼
Top-K
```

例如：

```text
Query

"TCP协议是什么？"
```

搜索：

```text
Candidate                Similarity

"什么是TCP？"                0.96
"TCP协议的作用是什么？"       0.93
"UDP是什么？"                0.71
"HTTP是什么？"               0.68
```

---

# 13. 为什么需要 Top-K

不能：

```text
只找最近的一个
```

而应该：

```text
Top K
```

例如：

```python
results = vector_store.search(
    vector=query_vector,
    top_k=5
)
```

然后：

```text
Top 5
 ↓
Threshold
 ↓
Safety
 ↓
最终 HIT
```

---

# 14. Similarity 使用什么？

最常见：

> Cosine Similarity

公式：

```text
              A · B
cos(A,B) = ─────────────
            ||A|| ||B||
```

范围：

```text
-1 ~ 1
```

Embedding 场景通常：

```text
越接近 1
越相似
```

例如：

```text
0.98 → 非常相似

0.90 → 比较相似

0.75 → 可能相关

0.50 → 基本不能认为相同
```

但是：

> **不要直接认为 0.9 永远就是 HIT。**

阈值必须通过数据集评估。

# 15. Threshold Policy

这是 Semantic Cache 最重要的策略之一。

例如：

```python
class ThresholdPolicy:

    def should_hit(
        self,
        similarity: float
    ) -> bool:

        return similarity >= 0.92
```

但是生产环境不能简单写死：

```text
threshold = 0.92
```

因为不同领域：

```text
技术问答
客服
代码生成
医疗
法律
Agent Tool Call
```

语义空间分布可能不同。

---

# 16. Threshold 应该怎么确定？

准备 Dataset：

```text
query_a
query_b
label
```

例如：

```text
"什么是TCP？"
"TCP是什么？"
1

"什么是TCP？"
"什么是UDP？"
0
```

然后计算：

```text
similarity
```

得到：

```text
Positive:
0.94
0.91
0.96
0.89

Negative:
0.62
0.71
0.68
0.75
```

选择：

```text
threshold = 0.88
```

使：

```text
False Positive
尽可能低
```

同时保证：

```text
Cache Hit Rate
足够高
```

---

# 17. 为什么 Semantic Cache 最大的问题是 False Positive

例如：

Query：

```text
"2024年苹果营收是多少？"
```

Cache：

```text
"2023年苹果营收是多少？"
```

Embedding 可能非常相似：

```text
0.96
```

但答案：

```text
完全不同
```

如果直接 HIT：

> **缓存反而会让 LLM 返回错误答案。**

所以 Semantic Cache 最大的风险不是 Cache Miss，而是：

> **错误命中。**

# 18. Safety Validator

所以必须增加：

```text
Similarity HIT
       ↓
Safety Validator
       ↓
真正 HIT
```

可以检查：

```text
model
system prompt
tenant
user
temperature
tools
knowledge base
time sensitivity
```

---

# 19. 最基础 Safety Validator

```python
class SafetyValidator:

    def validate(
        self,
        query,
        cached_entry
    ) -> bool:

        if query.model != cached_entry.model:
            return False

        if query.temperature != cached_entry.temperature:
            return False

        return True
```

# 20. Tenant Isolation

这个在你的 LLM Gateway 项目中特别重要。

假设：

```text
Tenant A
```

问：

```text
"公司2025年营收是多少？"
```

缓存答案：

```text
Tenant A 的内部数据
```

然后：

```text
Tenant B
```

问：

```text
"公司2025年营收是多少？"
```

如果只做：

```text
Embedding similarity
```

可能直接：

```text
HIT
```

导致：

> **跨租户数据泄露。**

所以 Cache Entry 必须带：

```text
tenant_id
```

并且查询时：

```text
WHERE tenant_id = current_tenant
```

这是一个必须实现的安全边界。

# 22. TTL

缓存不能永久有效。

例如：

```text
TTL = 1 hour
```

写入：

```text
10:00
```

那么：

```text
11:00
```

失效。

---

# 23. 为什么 Agent 特别需要 TTL

Agent 可能执行：

```text
Search
 ↓
Cache
 ↓
Decision
```

如果缓存：

```text
昨天的答案
```

Agent 可能基于旧数据：

```text
做错误决策
```

例如：

```text
"当前服务器状态是什么？"
```

昨天：

```text
healthy
```

今天：

```text
down
```

如果命中旧 Cache：

```text
healthy
```

Agent 就会继续执行错误流程。

所以：

> **语义相似 ≠ 语义有效。**

# 24. Invalidation

除了 TTL，还应该支持主动失效：

```text

      ↓

```

# 25. Version-based Invalidation

这是非常推荐 Agent 系统使用的方案。

Cache Entry：

```json
{
  "tenant_id": "tenant-A",
  "knowledge_version": "v42",
  "answer": "..."
}
```

当前知识库：

```text
version = v43
```

发现：

```text
v42 != v43
```

直接：

```text

```

这样不用遍历删除所有缓存。

# 31. Metadata Filter

不要直接：

```sql
ORDER BY embedding <=> :query_vector
LIMIT 5;
```

应该首先限制：

```sql
WHERE tenant_id = :tenant_id
  AND model = :model
  AND expires_at > NOW()
```

然后：

```sql
ORDER BY embedding <=> :query_vector
LIMIT 5;
```

这样：

```text
Tenant Isolation
+
TTL
+
Similarity
```

同时成立。

# 33. 为什么先 Exact Cache，再 Semantic Cache？

因为：

```text
Exact Match
```

成本非常低：

```text
Hash
 ↓
Redis
 ↓
O(1)
```

而 Semantic：

```text
Embedding
 ↓
Vector Search
 ↓
Similarity
```

本身也需要：

> **计算成本。**

所以：

```text
Exact Cache
     ↓
Semantic Cache
     ↓
LLM
```

比：

```text
Semantic Cache
     ↓
LLM
```

更合理。


# 35. 什么答案不能缓存？

这是项目必须考虑的。

例如：

```text
"现在几点？"
```

不应该长期缓存。

```text
"现在天气怎么样？"
```

不应该直接缓存。

```text
"帮我查询订单状态"
```

通常不应该缓存。

```text
"执行删除数据库"
```

绝对不能简单做 Semantic Cache。

# 36. Cacheability Policy

可以设计：

```python
class CachePolicy:

    def is_cacheable(
        self,
        request,
        response
    ) -> bool:

        if request.temperature > 0.7:
            return False

        if request.has_tools:
            return False

        if request.is_realtime:
            return False

        return True
```

# 42. 最重要的指标：Hit Rate

公式：

```text
Hit Rate
=
Cache Hits
/
Total Cache Requests
```

例如：

```text
10000 requests

3000 HIT
7000 MISS
```

那么：

```text
Hit Rate = 30%
```

---

# 43. 但是 Hit Rate 不是最终目标

假设：

```text
Hit Rate = 90%
```

但是：

```text
False Hit = 10%
```

这套 Cache 就非常危险。

所以至少看：

```text
Hit Rate
False Hit Rate
Token Saved
Cost Saved
Latency Saved
```

---

# 44. Token Saving

如果每次 LLM 请求：

```text
1000 tokens
```

10000 请求：

```text
10,000,000 tokens
```

Cache：

```text
Hit Rate = 50%
```

那么大致避免：

```text
5,000,000 tokens
```

生成。

所以：

> **Semantic Cache 的价值最终应该转换成 Token / Money / Latency。**

---

# 45. Cost Saving

例如：

```text
Input = $1 / 1M tokens
Output = $5 / 1M tokens
```

Cache Hit：

```text
无需调用 LLM
```

那么可以计算：

```text
saved_cost
```

并接入你第二个项目：

```text
TokenMeter
```

# 49. SemanticCache 核心伪代码

```python
class SemanticCache:

    async def get(
        self,
        request
    ):

        # 1. Normalize
        normalized = self.normalizer.normalize(
            request
        )

        # 2. Exact cache
        exact = await self.exact_store.get(
            normalized
        )

        if exact:
            return CacheResult.hit(
                exact,
                similarity=1.0
            )

        # 3. Embedding
        vector = await self.embedding.embed(
            normalized
        )

        # 4. Similarity Search
        candidates = await self.store.search(
            vector,
            top_k=5
        )

        # 5. Threshold
        candidate = self.policy.select(
            candidates
        )

        if not candidate:
            return CacheResult.miss()

        # 6. Safety
        valid = self.validator.validate(
            request,
            candidate
        )

        if not valid:
            return CacheResult.miss()

        # 7. HIT
        return CacheResult.hit(
            candidate.response,
            similarity=candidate.similarity
        )
```

# 50. Cache Set

```python
async def set(
    self,
    request,
    response
):

    if not self.policy.is_cacheable(
        request,
        response
    ):
        return

    normalized = self.normalizer.normalize(
        request
    )

    vector = await self.embedding.embed(
        normalized
    )

    entry = CacheEntry(
        tenant_id=request.tenant_id,
        model=request.model,
        prompt=normalized,
        embedding=vector,
        response=response,
        expires_at=time.time() + 3600
    )

    await self.store.insert(entry)
```
