# 07. Tool Execution Sandbox

## 1. 项目定位

项目名称：

```text
agent-tool-sandbox/
```

目标：

实现一个简化版 **Agent Tool Sandbox Runtime**，让 Agent 可以安全地执行：

```text
Python
Shell
SQL
```

但不能直接获得宿主机权限。

最终架构：

```text
                    Agent
                      │
                      │ Tool Call
                      ▼
              ┌───────────────┐
              │ Policy Engine │
              └───────┬───────┘
                      │
               policy decision
                      │
          ┌───────────┴───────────┐
          │                       │
        DENY                    ALLOW
          │                       │
          ▼                       ▼
       Reject              Sandbox Manager
                                  │
                                  ▼
                           Ephemeral Runtime
                                  │
                     ┌────────────┼────────────┐
                     ▼            ▼            ▼
                   CPU          Memory       Timeout
                     │            │            │
                     └────────────┼────────────┘
                                  │
                         ┌────────┴────────┐
                         ▼                 ▼
                    Filesystem        Network
                     Boundary          Egress
                         │                 │
                         └────────┬────────┘
                                  ▼
                              Execution
                                  │
                                  ▼
                               Result
                                  │
                                  ▼
                                Agent
```

# 3. 最核心的安全原则

整个项目建议围绕一句话：

> **Never trust model-generated code.**

也就是说：



因此：


而不是：

```text

 ↓
```

# 7. Execution API

核心 API：

```http

```

请求：

```json
{
  "type": "python",
  "code": "print(sum(range(100)))",
  "policy": {
    "timeout_seconds": 10,
```

```json

  "status": "success",

  "stderr": "",

```

# 10. Policy 是整个项目的核心

不要让 Agent 自己决定：

```json
{
  "network": true,
  "memory": "10GB",
  "timeout": "1h"
}
```

这是非常危险的。

应该：

```text
Agent Request
      ↓
Policy Engine
      ↓
Server-side Policy
      ↓
Compiled Sandbox Config
```

即：

> **Agent 可以请求能力，但不能决定最终权限。**

# 12. Policy Compiler

Policy Compiler 的职责：

```text
High-level Policy
       ↓
Validation
       ↓
Normalize
       ↓
Compile
       ↓
Sandbox Configuration
```

例如：

```python
class PolicyCompiler:

    def compile(self, policy):

        validate(policy)

        return SandboxConfig(
            cpu=policy.resources.cpu,
            memory=policy.resources.memory_mb,
            timeout=policy.resources.timeout_seconds,
            network_enabled=policy.network.enabled,
        )
```

---

# 13. 为什么需要 Compiler？

因为业务层：

```yaml
memory_mb: 256
network: false
```

并不是 Docker/Kubernetes 能直接理解的安全策略。

Compiler 要把它转换成：

```text
Docker HostConfig
SecurityContext
NetworkPolicy
Filesystem Mount
CPU Limit
Memory Limit
```

所以：

```text
Policy
```

是：

> **声明式安全策略。**

而：

```text
Compiler
```

负责：

> **把安全策略转换成底层 Runtime 配置。**

这是一个很重要的架构抽象。

# 16. 最小权限原则

例如 Agent 只需要：

```text

写 output
```

```text

```

原则：

> **Default Deny。**

不是：

```text

```

然后慢慢禁止危险路径。

例如：

```python

```


# 25. Temporary Runtime

每次执行：

```text
Execution
 ↓
Create Container
 ↓
Run
 ↓
Collect Result
 ↓
Destroy Container
```

不要：

```text
一个 Container
+
所有 Agent 共用
```

否则：

```text
Agent A
 ↓
留下文件

Agent B
 ↓
读取 A 文件
```

产生：

> Cross-Execution Data Leakage。

所以推荐：

```text
1 execution = 1 ephemeral runtime
```

# 27. Agent Tool 接入

最终 Agent 不直接操作 Docker。

应该定义：

```python
class CodeExecutionTool:

    async def execute(
        self,
        code: str
    ) -> ToolResult:

        execution = await sandbox.create(
            code=code
        )

        return await sandbox.wait(
            execution.id
        )
```

Agent：

```text
LLM
 ↓
Tool Call
 ↓
CodeExecutionTool
 ↓
SandboxManager
 ↓
DockerSandbox
```

这样以后可以换：

```text
Docker
 ↓
Kubernetes
 ↓
Firecracker
```

而 Agent 完全不用改。

# 28. Sandbox 抽象

```python
from abc import ABC, abstractmethod


class Sandbox(ABC):

    @abstractmethod
    async def create(self, config):
        pass

    @abstractmethod
    async def start(self, execution_id):
        pass

    @abstractmethod
    async def stop(self, execution_id):
        pass

    @abstractmethod
    async def kill(self, execution_id):
        pass

    @abstractmethod
    async def collect(self, execution_id):
        pass

    @abstractmethod
    async def destroy(self, execution_id):
        pass
```

然后：

```text
Sandbox
├── DockerSandbox
├── KubernetesSandbox
├── FirecrackerSandbox
└── WasmSandbox
```

# 42. 做完这个 Demo 后，你应该能回答的面试题

这个项目非常适合 Agent 基础设施面试，重点准备：

1. **为什么 Agent 执行代码不能直接 exec？**
2. **Docker 容器和真正的安全沙箱有什么区别？**
3. **为什么需要 Ephemeral Runtime？**
4. **如何限制 Agent 的 CPU / Memory / Disk / PID？**
5. **如何限制 Agent 访问宿主机文件系统？**
6. **如何限制 Agent 的网络访问？**
7. **为什么 Network Allow List 比 network=true 更安全？**
8. **Policy Engine 为什么不能让 Agent 自己决定权限？**
9. **Policy Compiler 解决什么问题？**
10. **Container 被打穿怎么办？**
11. **Docker Sandbox、Kubernetes Sandbox、gVisor、Firecracker、WASM 怎么选？**
12. **Agent Tool 执行超时后怎么保证进程真的被杀掉？**
13. **如何实现 Kill Switch？**
14. **如何防止恶意代码读取其他 Agent 的数据？**
15. **如何审计一次 Tool Execution？**

其中最值得你深入的是最后这个问题：

> **“Docker 已经隔离了，为什么还需要 Policy Engine？”**

答案是：

```text
Docker
解决：
Runtime Isolation

Policy
解决：
What is Allowed

两者不是一层。
```

也就是：

```text
                 Agent Security
                      │
          ┌───────────┴───────────┐
          │                       │
      Authorization            Isolation
          │                       │
       Policy                  Sandbox
          │                       │
          ▼                       ▼
     能不能做？                做了也不能影响谁？
```

**这就是第 07 个项目真正要学会的东西。** 做完它之后，你的第 06 个 `Async Agent Job Queue` + 第 07 个 `Tool Execution Sandbox` 就已经从“Agent 应用开发”开始进入真正的 **Agent Runtime / AI Infra Engineering** 了。
